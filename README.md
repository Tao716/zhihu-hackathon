# 会议纪要 → 决策 → 任务督办

一个适合飞书 AI 黑客松的最小闭环：从飞书文档读取会议纪要，调用 AI 提取决策和任务，经过人工确认后生成可下载的督办清单。

## 1. 本地启动

需要 Node.js 18+（当前代码使用原生 `fetch`，不需要安装依赖）。

```bash
cd meeting-to-action
cp .env.example .env
# 编辑 .env，填入你的配置
npm start
```

打开 <http://localhost:8000>（本地想使用 3000 端口时可运行 `PORT=3000 npm start`）。

没有配置任何密钥时，应用默认启用示例模式，便于先体验完整交互。示例模式用于本地验证，不应作为参赛 Demo 的最终运行方式。

## 2. 接入飞书文档

在飞书开放平台创建一个企业自建应用，并为应用配置读取文档所需的权限。把应用凭证填入：

```env
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=xxx
```

应用需要能够访问目标文档；分享链接中的文档 token 通常位于 `/docx/<token>`。如果链接是 Wiki 页面，建议在 Demo 前把页面内容同步到一个可直接读取的飞书文档，或在页面中提供文档 token。

## 3. 接入 AI

应用使用 OpenAI-compatible Chat Completions 接口，支持 DeepSeek：

```env
OPENAI_API_KEY=你的 DeepSeek API Key
OPENAI_BASE_URL=https://api.deepseek.com
OPENAI_MODEL=deepseek-chat
```

如果使用其他兼容服务，只需要替换 `OPENAI_BASE_URL` 和模型名。提示词要求模型只输出结构化 JSON，服务端还会做一次字段归一化。

## 4. 人工确认与督办清单

分析结果会先展示在页面中，用户可以修改任务标题、负责人和截止日期。点击人工确认后，系统记录确认时间，并支持下载 Markdown 格式的督办清单，方便粘贴到现有飞书文档或发送给团队。当前版本不依赖多维表或群机器人。

## 5. 参赛 Demo 建议

1. 准备一份脱敏的真实会议纪要，保留模糊表达、负责人和日期等真实信息。
2. 展示 AI 如何把“讨论内容”区分为“已决策”和“待确认问题”。
3. 明确展示人工确认按钮，再下载督办清单。
4. 用一次真实运行记录前后耗时，不要编造提效数字。
5. 一并提交本目录中的 Prompt、表格字段说明和启动步骤，增加复用价值。

## 6. 下一步可扩展

- 支持定时扫描“待处理”会议文档。
- 任务状态变化后自动生成周报和逾期提醒。
- 接入飞书文档写回或任务系统（按需启用）。
- 增加任务去重：避免同一会议重复生成。
- 给每条任务保留原文依据，方便追溯和复盘。

生产使用前还应补充登录鉴权、重试/幂等和更细的权限控制；当前版本重点是黑客松可演示的最小闭环。
